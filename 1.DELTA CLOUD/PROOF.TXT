Architecture Name: Microkernel Architecture
Definition: A microkernel architecture keeps a small, stable core system and moves optional or changing capabilities into plug-in components. This makes the core easier to keep stable while allowing the product to evolve through extensions. It is commonly used in systems that need customization, product variants, or plugin ecosystems. (Textbook — Fundamentals of Software Architecture, Chapter 12)
Justification: Deltacloud is a textbook Microkernel implementation. The core (BaseDriver, Collections::Base, Sinatra::Rabbit routing engine, shared models in lib/deltacloud/models/) is a small, stable nucleus that defines contracts — it never changes for individual cloud providers. The plug-in components are the 17+ independently loaded cloud drivers (ec2/ec2_driver.rb, openstack/, azure/, mock/mock_driver.rb, etc.), each loaded dynamically at startup via Deltacloud::Drivers.driver_config.each_key in drivers_initialize.rb. Each driver extends BaseDriver and overrides only the operations it supports. Additionally, the Feature system (drivers/features.rb) allows each plug-in to advertise optional capabilities (e.g., :user_data, :firewalls, :bucket_location) without touching the core. The frontend layer itself (Deltacloud API, CIMI API, EC2 API) is also plug-in-style, configured via frontend_initialize.rb and mounted at separate URL routes — the core runs unchanged regardless of which frontends are active.
